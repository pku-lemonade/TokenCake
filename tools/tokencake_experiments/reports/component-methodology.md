# 完整组件测试的方法与口径

## 实验范围

本次测试比较固定版本下的四种配置，在每个配置上运行 0.05、0.1、0.2、0.5、1.0 五档应用 QPS。
每个初始实验均执行完整 24-DAG，不截断后段请求。初始矩阵共 20 组、480 个 DAG、12,960 次模型调用。
正式结果使用 `/root/autodl-tmp/tokencake-optimization/components-final-01` 的独立记录。
调参诊断使用其他目录，其结果不混入正式矩阵。

报告组织参考论文的端到端性能、组件贡献和迁移开销分析。
论文使用的硬件、应用数量、到达分布和上传实现与本次测试不同，本次不是完整复现其数值结论。
参见 [TokenCake, §7.2、§7.3、§7.6](https://arxiv.org/html/2510.18586v4#S7)。

| 报告标签 | 驱动模式 | Agent 调度 | 工具窗口 KV 保存 | CPU KV 容量 |
| --- | --- | --- | --- | --- |
| base | native | 关闭 | 关闭 | 无 |
| agent | agent | 开启 | 关闭 | 无 |
| offload | offload | 关闭 | 开启 | 100 GiB |
| agent_offload | offload-agent | 开启 | 开启 | 100 GiB |

`offload` 关闭空间调度控制器，但保留生命周期元数据、工具事件和时间策略。
其中时间策略仍使用请求元数据中的重要性和保存资格，因此该配置表示独立开关对比，不能解释成完全去除 agent 上下文的 offload。
两种 offload 配置均使用当前 vLLM 的原生 CPU KV 存储和传输路径。
H2D 由后继请求的实际缓存命中触发，不将它描述成论文中的预测提前上传。

## 固定条件

- 模型：本地 Qwen2.5-14B-Instruct，BF16，TP=1、PP=1。
- GPU：每个服务独占一张 NVIDIA A800-SXM4-80GB，绑定对应 NUMA CPU 集合。
- 显存比例：0.5；最大上下文：32,768；原生批处理 token 预算：8,192。
- 每个服务实际具有 3,050 个 GPU KV block，每块 16 token；其中一个为原生 null block。
- 保留原生 prefix caching、异步调度、完整输入长度检查和分块 prefill。
- 所有配置关闭 speculative decoding；不使用提前结束抢占请求的语义。
- base 使用独立且未修改的原生 vLLM checkout，提交 `0b3ba88f165976e77ca5e6a7a3f5bba4562b80af`。
- 三种组件配置使用同一个目标 runtime，SHA-256 为 `a0672d391b65e83abc712d87af17741becc9c491a56a55314eb6c1cf475d954f`。
- 正式输入及到达序列的联合 SHA-256 为 `7eb8dff8e1f9457bd26eb817d90ddd35a6e2227358abf4700a27887a79672a5d`。

每一组都重新启动服务，清空进程内请求和 KV 状态。
同 QPS 的四种配置使用同一份冻结到达序列。现有驱动采用等间隔到达，偏移为 `index / QPS`，不是 Poisson 到达。
五档最后一个 DAG 的到达偏移分别为 460、230、115、46、23 秒。
这些到达间隔属于总 E2E 的测量区间。

GPU0 依次运行 base 和 offload，GPU1 依次运行 agent 和 agent_offload，各模式由高 QPS 向低 QPS 执行。
原生 GPU-only 测试可以并行；带 CPU offload 的服务之间串行。
容器的内存上限为 240 GiB，同时启动两个 100 GiB CPU KV pool 会压缩模型加载和 CUDA 的内存余量。
资源锁不改变任何服务的 CPU KV 容量，其等待发生在客户端计时前。
记录两张 GPU 的并行任务、温度、时钟、功耗、占用和进程归属，供解释硬件及并行运行差异。

## 负载及正确性

沿用已选择的 `conversation-tools` 负载，本轮继续优化期间没有再次修改 DAG、输出目标或工具等待时间。
每个 DAG 有 29 个执行节点和 36 条依赖边；每组有 648 次模型调用和 48 个本地节点完成记录。
每组必须生成 155,136 个输出 token，不能通过丢弃请求、缩短输出或减半输入来获得合格结果。
工具阶段按照工作负载声明的时长进行等待模拟，并非实际操作文件系统或调用外部搜索服务。

此前选择该负载时，已经采用追加式对话上下文，并将每个 DAG 中 13 个工具指令调用的输出目标设为 128 token。
相较早期原始负载，每组输出目标从 271,200 降为 155,136 token。
本次 base 与所有组件配置采用同样的目标，所以组间性能比较成立；该比较不代表原始工作量下的纯算法加速，也不证明任务质量等价。

冻结的是初始数据、DAG、输出预算及到达序列。
后续 prompt 包含上游生成内容，实际 prompt token 数按每次运行记录；不同批次执行的生成文本不要求逐字相同。
完整 DAG 验收检查工作量、完成状态、重试、输入缩减和配置一致性，未执行任务质量评分。
独立真实模型服务测试另外覆盖受压恢复、CPU KV 回载及输出检查。

## 最终调度行为

1. 等待请求保留 agent/DAG 重要性评分，并将 join 组中关键分支的优先级传给其依赖分支，减少关键分支等待低优先级依赖的情况。
2. 动态 KV 预留和借用主要作用于新准入。已接纳请求增长时产生的预留账目超额，由后续准入和容量释放逐步消化，避免因预留比例调整反复失去执行资格。
3. 准入使用原生多缓存组需求计算，逻辑计入所有已接纳请求的剩余输入与生成预算。真实 KV 仍逐步分配，不提前分配整个请求的缓存，也不另建 GPU 内存池。
4. 物理分配失败仍可抢占。先限制候选的重要性范围，再比较实际可释放 block 和预计重算 token，尽量保留接近完成的请求。重算成本不与重要性分数或毫秒直接相加。
5. 被抢占请求保留其执行语义，重新准入时检查未承诺容量或其他请求完成情况是否改善，防止立即重演同一容量失败。
6. `decode_prefill_token_budget=0` 使用原生 prefill 预算。共享 GPU KV 的排序偏好只在压力下、分数差不超过 500 且共享收益足够时生效。
7. 工具窗口内保存已完成生成的可复用前缀，检查时间窗口、等待需求、CPU 容量与传输成本；后继请求通过原生缓存命中路径恢复。

本轮新增的默认策略是对所有已接纳请求承诺生成预算，`generation_reserve_mode=all`。
其余上述机制是最终版本保留的优化，不能将它们全部算成本轮新增改动。
扩大共享 KV 分数范围至 1000 的诊断未确认额外总 E2E 收益，因此最终保持 500。

## 指标定义

| 指标 | 解释 |
| --- | --- |
| 总 E2E | 客户端进程启动到退出，包含到达间隔和完整 DAG 的排空；不含服务初始化 |
| 应用时延 | 单个 DAG 开始执行到完成，报告均值、P50、P90、P95、P99 和最大值 |
| 完成吞吐 | 完成 DAG 数或输出 token 数除以总 E2E，描述本次有限负载的完成速率 |
| 物理抢占 | TokenCake 记录的实际物理分配不足引发的抢占 |
| 预留抢占 | 预留策略引发的抢占，与仅拒绝准入的计数分开 |
| 准入拒绝 | 每次调度尝试的策略或逻辑容量拒绝；同一请求可被反复计数，不等于拒绝的请求个数 |
| 实际重算 token | 已返回模型执行结果中的 token 位置，与同一请求此前执行区间的交集 |
| 首次 prefill 来源 | 原生统计的首次输入计算、GPU prefix 命中和外部 CPU KV 命中，不包含抢占后重复 prefill |
| 恢复 GPU/CPU 命中 | 已被抢占请求再次准入时的命中 token，只在启用调度观测的配置中可用 |
| 重要请求等待 | 动态关键 agent 类型或显式 critical_path 请求的准入等待，记录最大值和阈值次数 |
| 关键节点 LLM 时延 | 冻结 DAG 中显式关键节点的调用时延，包含排队、服务和调用开销；四种模式均可比较 |
| KV 占用 | 原生 KV block 占用指标，按客户端区间进行时间加权 |
| GPU 活跃度 | `nvidia-smi` 的硬件利用率，按客户端区间时间加权，不等于有效 KV 使用率 |
| D2H/H2D 开销 | 原生传输的字节数、作业数和累计时间；重叠作业的累计时间不是可从 E2E 直接扣除的串行部分 |

关闭空间调度时，TokenCake 的调度计数器可能仍导出初始零值，但未进行实际执行观测。
分析器将这些值标为 N/A。原生 vLLM 同样不暴露这里使用的实际重算区间统计。
保留原生总抢占次数及首次 prefill 来源，不能把缺失的重算量解释为零。

KV 占用由原生空闲 block 队列计算，已释放引用但仍保存可命中前缀的 block 可以处于空闲队列中。
因此占用为零不表示 GPU 上没有可复用前缀，平均占用降低也不等于预分配的 CUDA KV buffer 变小。
本报告不将该指标解释为论文中的有效 KV 使用率。

时间加权使用单调时钟，将样本裁剪到客户端测量区间；超过 10 秒的采样空洞不向前填补。
报告同时保留采样覆盖率。关键路径通过实际最晚完成的前驱回溯，分解 LLM、工具、剩余处理和编排间隙，逐个 DAG 核对其和等于应用时延。
不同并行分支的耗时不会直接相加为端到端时延。

动态关键请求的集合会随调度状态变化，其准入次数并非固定样本量。
固定 DAG 则在每组中标注了同样的 408 次关键节点模型调用，使用这些调用的均值和 P95 辅助跨配置比较。

## 统计与结论边界

表格按每组合格运行的指标中位数汇总，保存全部单次结果及排除原因。
明确标注的观测最大值和最低采样覆盖率使用对应极值；关键准入等待同时保留最大值的中位数和所有运行中的实际最大值。
接近既定验收边界时，沿用原有最多三次启动的复测规则，不删除较慢的合格运行。
图中的范围线表示实际最小值与最大值，不是置信区间；只有一次运行时，不声称已证明统计稳定性。
来源堆叠图和应用 CDF 使用 E2E 中位数对应的同一次实际运行。
来源各分项不能先独立取中位数再堆叠，否则其和不一定对应任何一次实际运行的输入总量。

25% 目标使用总 E2E 降幅 `(T_base - T_agent_offload) / T_base`。
在固定完成工作量下，E2E 降低 25% 对应完成吞吐提高 33.3%，两种百分比不混用。

24 个 DAG 在同一服务中相互竞争，不是 24 次独立系统实验。
有限负载的完成吞吐不能直接等同于稳态可持续 QPS，也不能单凭所有请求完成就证明任意持续负载下都没有饥饿。
报告按各 QPS 单独列出相对 base 的变化，不用平均值掩盖某个负载点的退化或未达到 25% 的情况。
